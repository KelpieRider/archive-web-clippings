# 目录结构

## 新项目

```text
<项目名>/
├─ index.html
├─ 00-范围与入口.md
├─ 01-网站关系.md
├─ 02-处理记录.md
├─ 03-完整性测试.md
├─ pages/
└─ assets/
   ├─ 000001/
   └─ 000002/
```

抓取期间不要创建空的附件目录。只有某个页面确实需要猫抓补充资源时，才建立对应的 `assets/<页面ID>/`。`index.html` 和 `03-完整性测试.md` 在最终完整性测试时生成。

页面 ID 使用六位递增数字。SingleFile 文件名采用：

```text
<页面ID>__<主机名>__<简短标题>.html
```

清理文件名中的 Windows 禁止字符，保留原始标题和网址到关系表中，不要只依赖文件名恢复来源。

# 关系记录

## `01-网站关系.md`

关系表既是来源图谱，也是续跑队列。每个规范化网址一行：

```markdown
# 地址图谱

## 页面与候选

| ID | 状态 | 边界 | 相关性 | 标题 | URL | 父ID | 关系类型 | 判断证据 | 本地页面 | 附件目录 | 最近检查 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 000001 | 已保存 | 范围内 | 强 | 示例文章 | https://example.com/post/1 | 入口 | 作者主页直达作品 | 页面署名与目标账号一致 | pages/000001__example.com__post-1.html | assets/000001/ | 2026-09-04T18:30:00+08:00 |
```

字段规则：

- `边界`：只能写 `范围内` 或 `范围外`。跨域不等于范围外，同域也不等于范围内，按用户确认的作者或主题边界判断。
- `父ID`：发现该网址的页面 ID；入口使用 `入口`。
- `关系类型`：例如作者作品、分页、附件、原始来源、引用、主题延伸或站外索引。
- `判断证据`：写可以复查的事实，不写“看起来有关”一类空泛结论。
- `本地页面` 和 `附件目录`：没有生成时留空，不填不存在的路径。
- 一个网址经重定向后，把最终网址写入本行，并在判断证据中保留原网址。

# 处理记录

## `02-处理记录.md`

按批次追加，不覆盖以前的记录：

```markdown
# 抓取批次

## 2026-09-04 18:30 +08:00

- 页面ID：000001
- 操作：SingleFile 保存；猫抓补充 3 个懒加载图片
- 验证：正文、样式和 8 张主要图片可本地打开
- 缺口：评论需要联网，未保存
- 新候选：000002、000003
- 大文件决定：无
```

出现失败时记录具体阶段和可重试条件，例如“SingleFile 已保存，但本地第 4 张图片为空；猫抓未发现资源”，不要只写“抓取失败”。

# 更新顺序

## 每页完成后

1. 先更新 `01-网站关系.md` 当前页面状态与新候选。
2. 再向 `02-处理记录.md` 追加本次结果。
3. 最后更新 `00-范围与入口.md` 的断点。

三处写入都使用 UTF-8。若中途失败，至少保证断点指向尚未完成的页面，避免下次误判为已保存。

# 剪报入口

## `index.html`

由最终审计脚本生成，列出所有状态为 `已保存` 且本地文件存在的页面。页面标题优先采用关系表中的 `标题`；没有标题时才显示原网址。入口中的链接全部使用本地相对路径。

# 完整性记录

## `03-完整性测试.md`

至少记录测试时间、检查页面数、本地导航数量、在线回退数量、丢失页面文件、无法恢复的引用和联网资源，以及最终判断。一级标题使用“测试结果”，不要使用文件名。

“本地归档完整”和“联网时可继续浏览”是两个不同结论：图床、CSS、脚本或音视频保留原网址时，页面仍可使用，但必须说明它依赖网络，不能声称完全离线。
